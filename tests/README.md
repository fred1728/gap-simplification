# Test guide

The tests in this directory check the implementation loaded by `fred2.g`.
They use small, explicit examples with known expected results so that changes
to the algorithms can be checked for regressions.

## Running the tests inside GAP

Start GAP with the repository root as its working directory, then run:

```gap
Read("tests/core.g");
Read("tests/integration.g");
# Optional, slower regression using the reported SL3Zs example:
Read("tests/sl3zs.g");
```

Each file can also be run independently. The core suite requires GAP; the
integration suite loads HAP and requires its dependencies to be installed.
Without HAP, loading the core suite may print unbound-global warnings for
`HapNonFreeResolution` and `CanonicalRightCountableCosetElement`; the core
checks do not use those HAP features.

Successful runs print:

```text
PASS: fred2 core tests
PASS: fred2 HAP integration tests
```

The tests leave GAP running. A failed comparison prints its label, expected
value, and actual value, then raises an error. Type `quit;` at the break-loop
prompt to return to the session. Continuing with `return;` can allow execution
to reach a PASS message despite the earlier failure, so any reported failure
means the run did not pass.

The scripts assign globals such as `L`, `U`, `FL`, `R`, and `S`, so they can
overwrite variables with those names in an existing session.

Alternatively, from a terminal:

```sh
./tests/run.sh              # Core suite
./tests/run.sh integration  # Integration suite
./tests/run.sh all          # Both suites in one GAP session
```

These commands also leave GAP open when run interactively.

## Shared example and comparison helper

`helpers.g` defines two functions:

- `Fred2Check(actual, expected, label)` compares values using GAP equality
  and raises an error if they differ.
- `Fred2Interval(reverse)` creates an interval subdivided into two edges,
  with three vertices. Vertex 1 is the shared center; vertices 2 and 3 are
  the endpoints. Its group and stabilizers are trivial. Passing `true`
  reverses the second edge's orientation.

The interval has this incidence pattern; the drawing omits orientations:

```text
vertex 2 ---- vertex 1 ---- vertex 3
         edge 1       edge 2
```

## Core suite: `core.g`

The core suite checks the smaller operations used during simplification.

| Operation | What is checked |
| --- | --- |
| `kStar` | The center's star contains one vertex and two edges, with edge indices 1 and 2 and identity representatives. |
| `ForgetG` | Forgetting the group action produces the expected relative incidence lattice, containing the center and its two incident edges. |
| `IsGBalanced` | The star is balanced for the trivial action. |
| `Stabstar` | The star stabilizer is the trivial group in this example. |
| `Cobound` | The center has both edges as cofaces, and the edges have no higher cofaces. |
| `EntireBoundary` | The vertex has no boundary, and an edge has the center as its boundary within the relative lattice. |
| `ShouldRemove` | The shared center is removable; a missing cell and the tested top-dimensional cell are rejected. |
| `JoinCells` | Joining the two edges gives the expected lattice with one merged cell. |
| `SimplifyLattice` | Simplification produces the expected lattice and signs `[1,1]`; recomputing the input incidence lattice gives the original value. |
| `HomeomorphicToDisk` | The center's star passes the implemented collapse criterion, while the endpoint's star does not. This checks the criterion's behavior, not a general topological classification. |
| Orientation tracking | Reversing the second edge changes the merge signs to `[1,-1]`. |

Additional examples exercise behavior beyond the trivial interval:

- **Nontrivial stabilizer:** the group generated by `(1,2)` fixes the center
  while the edges have trivial stabilizers. The star contains four edge
  entries, accounting for translates of both edges. It remains balanced,
  and its stabilizer is the group generated by `(1,2)`. A modified example
  with a trivial center stabilizer and changed boundary data must be
  detected as unbalanced.
- **Incomplete element tables:** a stabilizer of order 12 must remain of
  order 12 when `L!.elts` contains only a subgroup of order 4. Adding more
  elements to that table must not change the computed stabilizer.
- **Balance checks beyond the element table:** subgroup generators must
  detect overlaps even when the relevant element is absent from `L!.elts`.
  A noncommuting example checks the order of multiplication when comparing
  translated cells and their conjugated stabilizers.
- **Triangle boundary:** an explicit incidence lattice for a filled triangle
  checks that `EntireBoundary` returns all three vertices and all three
  edges exactly once. This exercises traversal through multiple dimensions.

## Integration suite: `integration.g`

This suite checks how replacement and reduction work together on the
subdivided interval. HAP is needed to construct the replacement object.

| Check | Expected result |
| --- | --- |
| `Replace2(L,1,0,1)` cell counts | Two vertices, one edge, and no 2-cells: `[2,1,0]`. |
| Replacement boundary | The remaining edge uses the renumbered endpoints with signed boundary entries `[[1,1],[-2,1]]`, compared without regard to list order. |
| Reversed edge boundary | Requesting the boundary of edge `-1` reverses the signs, giving `[[-1,1],[2,1]]`, again compared without regard to order. |
| Replacement stabilizer | The remaining edge has trivial stabilizer. |
| Replacement action | The identity acts with orientation sign `1`. |
| `ReduceGComplex(...)` | Reduction gives two vertices and one edge. |
| Repeated reduction | Reducing again preserves those cell counts and the edge boundary. |

The final two interval comparisons check idempotence for the tested counts
and boundary; they do not compare every field of the resulting objects.

The integration suite also runs `attaching.g`, described below.

## Stars below the top dimension: `attaching.g`

Run this suite on its own with `Read("tests/attaching.g");`, or as part of
`integration.g`. It requires HAP and checks:

- Merging two boundary edges of a filled triangle leaves the 2-cell and
  attaches it once to the merged edge.
- Reversing a constituent edge preserves the correct attaching sign.
- A boundary that traverses the triangle twice retains multiplicity two.
- Negatively oriented attaching cells have the negated boundary.
- A 3-cell attached to two copies of the triangle keeps its boundary.
- A reflection exchanging the constituent edges gives one attachment
  with the correct orientation action on the merged edge.
- Extending that example to the group S3 gives orientation signs of `1`
  or `-1`, including outside the stabilizer, and respects its orientation
  character.
- Full reduction of a triangle works without the top-dimension restriction,
  including the resulting loop's zero cellular boundary.

The suite explicitly expands boundary-of-boundary and checks that it is
zero, collecting translated cells using their stabilizers and orientation
signs. This catches errors that cell-count checks alone cannot detect.

The original bug replaced each constituent face by the whole merged cell.
For example, if `E = e1 + e2`, an attaching boundary `e1 + e2 - f` must become
`E - f`, not `2E - f`. The replacement now collects contributions for each
translated star, accounts for orientation, and divides by its number of
constituent top cells. It verifies the result by expanding back into the
old cell module. This preserves genuine attaching multiplicities instead
of merely discarding duplicate terms.

## SL3Zs homology regression: `sl3zs.g`

This separate, slower test runs the reported example directly, without
barycentric subdivision:

```gap
Read("tests/sl3zs.g");
```

It constructs `ContractibleGcomplex("SL3Zs")`, reduces it without the
`n+k=d` restriction, and compares integral homology in degrees 0 through 4
using free resolutions with parameter 5. It prints both lists and asserts
that they agree. The verified result is:

```gap
[ [ 0 ], [ ], [ 2, 2 ], [ 12, 12 ], [ 2 ] ]
```

This test is not included in the terminal runner's `all` option; run it
explicitly inside GAP. Like the other tests, it leaves GAP open.

## Bianchi homology regression: `bianchi.g`

Run the reported Gaussian Bianchi example separately with:

```gap
Read("tests/bianchi.g");
```

The test constructs `BianchiGcomplex(-1)`, takes its barycentric subdivision,
and reduces that subdivision. It then compares homology in degrees 0 through
3 for the original, subdivided, and reduced complexes. All three should give:

```gap
[ [ 0 ], [ 2, 2 ], [ 6 ], [ 4, 24 ] ]
```

Reduction deliberately happens **before any homology calculation**. HAP can
extend the complex's element table while constructing a free resolution;
computing homology first could hide the original bug. That bug used only
`L!.elts` to generate the star stabilizer and, in this example, replaced a
stabilizer of order 12 by a subgroup of order 4. The corrected calculation
uses the full center stabilizer and checks balance with subgroup generators
and translated-cell cosets.

This test requires HAP, is separate from the terminal runner's `all` option,
and leaves GAP open.

## Homology comparison: `../testReduce.g`

The separate root-level file `testReduce.g` defines `TestGReduce(K)`.
Reading that file defines the function but does not run a test. It is not
included in `tests/run.sh`.

With HAP loaded and a suitable G-complex assigned to `K`, use:

```gap
LoadPackage("hap");
Read("testReduce.g");
TestGReduce(K);
```

The function:

1. Determines the dimension `d` of `K`.
2. Forms its barycentric subdivision `KK`.
3. Reduces `KK` to a complex `L` using `ReduceGComplex(KK)`.
4. Builds free resolutions through parameter `d+2`, tensors them with the
   integers, and computes homology in degrees `0` through `d+1` for each
   of `K`, `KK`, and `L`.
5. Prints the three homology lists in that order and returns whether the
   lists for `K` and `L` are equal.

The subdivision's homology list is printed for inspection but is not part
of the returned comparison. A `false` result reports a mismatch without
raising an assertion error. This function does not quit GAP.

## Scope and limitations

These are small regression tests, not a proof that simplification preserves
every G-complex. The integration suite covers intervals, triangles, reflected stars,
and a boundary update beneath a 3-cell. The optional SL3Zs and Bianchi tests cover reduction of two specific
complexes with nontrivial actions.

Homology preservation is checked by the optional SL3Zs and Bianchi regressions or by
separately calling `TestGReduce(K)`, and only for the selected degrees and
inputs.
The older root-level `test.g` and `testkstar.g` are exploratory scripts;
they are not part of the automated suites described above.
